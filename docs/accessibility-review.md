# Accessibility review scope

The available checks cover source and actual server-rendered markup, not a complete accessibility audit. Next ESLint's JSX accessibility rules pass. Production HTTP checks assert document language, one main landmark and h1, a focusable skip destination, unique IDs (including both demo copies), real same-document fragment destinations, accessible label references and associated input/textarea labels on homepage, all cases and 404. The skip-destination assertion failed first and drove adding tabindex=-1 to every main. Illustrative project art now has an image role and descriptive label; its internal SVG is decorative.

Text palette pairs measured earlier meet at least 4.5:1 for normal text (minimum tested pair 5.29:1). CSS includes visible focus, minimum mobile action sizes, wrapping content, dynamic-viewport dialog bounds and a reduced-motion override. Native dialogs provide platform modal mechanics; no custom trap is claimed tested. Empty personal data is omitted and sample data is labeled.

Still required: render 360/390/tablet/laptop/desktop, keyboard-only homepage→case→contact and guided journeys, mobile menu Escape/selection focus, dialog entry/exit/return, 200%/400% zoom and reflow, actual reduced-motion behavior, horizontal overflow/console checks, automated axe in the browser, and manual NVDA or equivalent screen-reader review. Browser host is unavailable, so these were not performed. No WCAG conformance claim or clean axe result is made. The share-card PNG was separately rendered and inspected; that is not website accessibility verification.
