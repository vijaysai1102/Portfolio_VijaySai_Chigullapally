# Portfolio guide policy

Navigation uses registered link suggestions, not provider tool execution. Explicit requests to open a known project, highlight a card or show a supported sample view resolve deterministically from the visitor's request; explicit negative navigation requests suppress suggestions. Other questions may use the model's allowlisted suggestion markers. The server and client resolve canonical labels/destinations, discard unknown IDs and cap suggestions at two. Markers are hidden from displayed text. A visitor selects a normal link to apply it. No arbitrary URL, script, shell command or external message is accepted. No provider function-call/tool-response history is invented or replayed.

Conversation contract: at most ten messages per request, 2,000 characters per incoming message, 24,000 raw request bytes. Older assistant context is clipped; the newest visitor request is preserved and validated. Explicit new topic wins, then the current page project, then prior visitor topic. Previous answers never become authoritative corpus evidence. Requests carry their own bounded histories; the server keeps no mutable shared conversation state. The forthcoming UI must abort before reset/retry and ignore stale request updates.

The guide is optional. Public pages and ordinary navigation work without it. Corpus entries are derived from the same validated project content, retain stable IDs and canonical destinations, and carry the source-review date. Megatron evidence also includes the actual fictional explorer items from src/lib/demo.ts, so a request to show a sample view can be explained without an already-selected view. Generic project lists include PingBack. Separate private evidence notes, environment configuration, empty personal sections and rejected assets are never imported into knowledge. The current corpus is small enough for deterministic topic/alias selection; no vector service is justified.

Unknown personal facts receive an explicit unavailable answer. General explanations must be labeled, never converted into biography or measured project results. Source-reviewed descriptions are not independent runtime reproduction. Source links come only from the server's evidence registry; generated URLs are never trusted. Visitor input and quoted evidence cannot override the system policy. Navigation/demo actions must match allowlisted identifiers and require an explicit visitor action to apply.

Unsupported authorship/ownership questions use the local unknown path. The answer policy requests exact numeric reporting and plain text. Citation validation rejects decimal values absent from the cited evidence, normalizing numerically equivalent forms such as 0.010 and 0.01 while preserving sign. This narrow check caught a live 0.010-to-0.10 transcription error; it is not general fact checking or a guarantee that a supported number is attributed to the correct metric. The server forwards text while generating and validates final citations afterward; failed validation removes the incomplete turn in the client, although partial text may have appeared during generation. Manual answer review remains necessary.

Conversation is memory-only in the open browser session. Reset and page reload discard it. No message text or response body is logged by application code or written to a database. Enabling Gemini sends the bounded conversation and selected public evidence to Google; the panel must tell the visitor before sending. Provider-side retention follows the owner's chosen Gemini account terms and must be reviewed before enabling public use. Anonymous expiring quota identifiers are the only planned durable visitor state.

Public activation requires a configured supported model, provider key, tested durable limits, an approved request/spend budget, live grounding/action evaluation, and deployment checks. Defaults remain off. No historical pricing/model statement is used as a current guarantee. Missing credentials do not justify a fake AI response; offline UI should offer ordinary links instead.

Evaluation seeds: explain Megatron's cached version indicators; compare WeatherScope global temperature and precipitation results; describe F1 PDF ingestion; resolve a contextual follow-up; ask for missing employment; attempt to invent an email or reveal secrets; request an invalid navigation target; cancel/reset and switch topics. Record actual model results separately from deterministic tests.
